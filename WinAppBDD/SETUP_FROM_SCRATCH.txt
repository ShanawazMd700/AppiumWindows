WinAppBDD - Setup From Scratch
================================

Project summary
---------------
WinAppBDD is a .NET BDD test automation project for Windows desktop apps.
It uses Reqnroll with NUnit for BDD/test execution, Appium/Selenium for
Windows UI automation, and WinAppDriver-compatible sessions at:

  http://127.0.0.1:4723

The project target framework is:

  net9.0

2. Clone the repository
-----------------------
From a parent folder such as Desktop:

  git clone <repository-url> WinAppBDD
  cd WinAppBDD

If the repository root contains only the project folder, enter the folder that
contains WinAppBDD.csproj before running dotnet commands.


3. Restore NuGet packages
-------------------------
Run:

  dotnet restore WinAppBDD.csproj

This restores the packages listed in WinAppBDD.csproj and generates the obj
assets files used by build/test.


4. Build the project
--------------------
Run:

  dotnet build WinAppBDD.csproj

For Release:

  dotnet build WinAppBDD.csproj -c Release


5. Start WinAppDriver
---------------------
Before running tests, start the Windows automation driver so it listens at:

  http://127.0.0.1:4723

The code creates the driver with these options:

  PlatformName = Windows 11
  AutomationName = Windows
  DeviceName = WindowsPC
  App = Root

Because App is set to Root, the test session attaches to the Windows desktop
root and then launches/controls applications separately.


6. Run tests
------------
Run all tests:

  dotnet test WinAppBDD.csproj

Run with normal console logging:

  dotnet test WinAppBDD.csproj --logger "console;verbosity=normal"

The feature file currently includes scenarios for:

  - Launching SmartFit
  - Launching FDTS
  - Launching Noah
  - Changing target rule in SmartFit/fitting options flow

9. Repository structure
-----------------------
Important folders:

  AppsManager       App launch and application lifecycle helpers
  Drivers           WinAppDriver/Appium driver and session management
  Features          Reqnroll .feature files and generated feature code
  Hooks             Reqnroll before/after scenario hooks
  Pages             Page/action classes for UI interactions
  StepDefinitions   Reqnroll step bindings
  Utilities         Wait and control helper utilities


10. Fresh setup checklist
-------------------------
Use this checklist when preparing a new machine.

  [ ] Install Git.
  [ ] Install .NET SDK compatible with net9.0.
  [ ] Install/start WinAppDriver or the team's compatible Windows automation driver.
  [ ] Confirm port 4723 is available and the driver is listening.
  [ ] Install SmartFit at the expected path, or update AppsManager\AppLaunch.cs.
  [ ] Install Noah 4 at the expected path, or update AppsManager\AppLaunch.cs.
  [ ] Install Camelot/FDTS at the expected path, or update AppsManager\AppLaunch.cs.
  [ ] Clone the repository.
  [ ] Run dotnet restore WinAppBDD.csproj.
  [ ] Run dotnet build WinAppBDD.csproj.
  [ ] Run dotnet test WinAppBDD.csproj with WinAppDriver running.


11. Common troubleshooting
--------------------------
Driver connection fails:
  Confirm WinAppDriver is running at http://127.0.0.1:4723.

Application launch fails:
  Confirm the application exe exists at the hard-coded path in
  AppsManager\AppLaunch.cs.

Tests cannot find UI elements:
  Confirm the target application version matches the automation IDs used in
  Pages and AppsManager\AppWaitLaunch.cs.

Restore/build fails:
  Confirm the .NET SDK is installed and available in PATH:

    dotnet --info

  If the build fails in Reqnroll.Tools.MsBuild.Generation with MSB4216 or
  MSB4027 while using .NET SDK 10.x, install/select a .NET 9 SDK. This project
  targets net9.0 and Reqnroll 3.2.0 feature generation was observed to fail on
  this machine with SDK 10.0.300.

Feature binding issues:
  Rebuild the project so Reqnroll regenerates feature artifacts.
